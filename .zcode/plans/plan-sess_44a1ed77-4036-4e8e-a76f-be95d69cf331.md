## 2. Double-click top area — behave like any other Mac app
The window has a transparent/hidden title bar (`fullSizeContentView`, `isMovableByWindowBackground`), so AppKit's double-click-titlebar behavior never fires — that's why other apps expand and this one doesn't.

`WindowMover` in RootView.swift:
- Attach one `NSClickGestureRecognizer` (`numberOfClicksRequired = 2`, `delaysPrimaryMouseButtonEvents = false`) to `window.contentView`, guarded against duplicate attachment (configure runs repeatedly). Single clicks, drags, and traffic lights stay instant.
- Small `NSObject` helper (selector target; `WindowMover` is a struct) handles the gesture: only when the double-click lands in the top ~40 pt strip (the floating-titlebar zone, full window width).
- Action honors the System Settings › Desktop & Dock › "Double-click a window's title bar" preference (`AppleActionOnDoubleClick`), which is exactly what normal Mac apps do: 1 = minimize, 3 = fill screen (native fullscreen), 0 = do nothing, absent/other = **zoom** (`window.zoom(nil)`) — so on your Mac, where other apps expand, this app will expand the same way, and double-click again restores the previous frame.

## 3. Dock-icon reopen after closing the window
`macapp/Sources/LessonTranscriber/App.swift` + RootView.swift
- Add `NSApplicationDelegateAdaptor` with an AppDelegate implementing `applicationShouldHandleReopen(_:hasVisibleWindows:)`: when no window is visible, post a `.reopenMainWindow` notification and return true.
- Give the `WindowGroup` an `id: "main"`; in RootView, `.onReceive(NotificationCenter.publisher(for: .reopenMainWindow))` calls `openWindow(id: "main")`. Closing the red button leaves the app running (standard macOS) and clicking the dock icon brings the window back.

## 4. Slight fade-in at launch
In `WindowMover.configure`, one-time (static guard): `window.alphaValue = 0`, then animate to 1 over ~0.25 s ease-out via `NSAnimationContext` — the whole window fades in like a native launch. Runs once; dock-reopens don't re-fade.
