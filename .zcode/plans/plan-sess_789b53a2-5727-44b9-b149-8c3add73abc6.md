## Your questions, answered from today's measurements

**"After the first launch, will close-and-launch always be quick?"** Yes. The 2.5-min ANE compile is one-time per installed version: macOS caches the compiled result, and the same app relaunches in 0.1–0.3 s (measured across processes). Only two things ever re-trigger it: installing an app update (freshly signed binary) and macOS updates. Ordinary daily use never pays it again.

**"Can we speed up the compile itself?"** No. It runs inside Apple's ANECompilerService; there is no public API to pre-compute it on a build machine, ship the output in the DMG, parallelize it, or tune it. The only levers that exist are avoiding the ANE entirely (transcription would get much slower — the ANE is why chunks transcribe fast) or the int8 encoder (might compile faster, unverified — you said skip that experiment). So the plan below makes the one-time cost *visible and honest* instead, and stops holding the model in memory afterwards.

## Implementation

**1. `macapp/Sources/LessonKit/TranscriptionEngine.swift` — progress broadcasting + unload**
- Replace the swallowed-progress behaviour: keep a per-precision registry of active progress handlers (guarded by the existing lock). `loadModels` registers the caller's handler for the duration of the load; when a caller joins an already-running load (the prewarm/first-transcription race), it immediately receives a replay of the last `StageUpdate`, then live updates. This fixes the silent-hang bug where a transcription starting during warm-up sat at ~2% with no feedback.
- Add `public func unloadModels()`: under the existing lock, clear `models`, `managers`, and `loadedPrecision` so ARC releases the 447 MB MLModel and ANE resources.

**2. `macapp/Sources/LessonTranscriber/AppState.swift` — observable warm-up state + 10-min idle unload**
- Add `@Published var modelWarmupStage: String?` — non-nil means "footer indicator visible".
- `prewarmModel()`: pass a real progress handler instead of `{ _ in }`; hop `StageUpdate.stage` to the main actor into `modelWarmupStage`; set it back to `nil` when the load settles (success or failure).
- Idle unload, "after 10 min idle" policy: when a transcription job settles (a `defer` in the job `Task` — the single point both success and error paths pass through), schedule a 10-minute `Task` that calls `engine.unloadModels()`. Starting a new transcription cancels any pending unload (so a fresh load isn't yanked back out) and the cycle repeats. `unloadModels` clearing everything also makes the fp16↔int8 setting switch reload the right encoder next job.

**3. `macapp/Sources/LessonTranscriber/Views/RootView.swift` — footer indicator above the version**
- Convert `versionFooter` (line ~106) into a VStack: when `state.modelWarmupStage` is non-nil, show a small line above "Version 1.1.1" — mini spinner (`ProgressView().controlSize(.mini)`) + the stage text, `.font(.footnote)`, `.foregroundStyle(.secondary)` — matching the existing status-line patterns (e.g. the "Summarising…" line). Hidden the moment loading finishes. The job's ProgressCard meanwhile shows "Loading speech model…" with a determinate bar head, thanks to the broadcasting fix.

**Verification:** build with `DEVELOPER_DIR=/Applications/Xcode.app swift build` (per project memory, CLT lacks the SwiftUI macros), run `ltctl merge-test`, then you launch the app once manually: first launch shows the warm-up line in the sidebar footer until the compile finishes; closing and reopening shows nothing (warm). One honest caveat the UI now surfaces: today's tests showed the warm cache can occasionally miss (a different binary re-paid it), so if a reload ever *is* slow, you'll see honest "Loading speech model…" progress in the footer and job card instead of a silent hang.
